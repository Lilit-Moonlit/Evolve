# 🤖 CFC Project — Multi-Agent Coordination Protocol

## ⚡ MANDATORY RULES FOR ALL AGENTS

> **STOP. READ THIS BEFORE DOING ANYTHING.**
> You are one of several AI agents working in this project simultaneously.
> Breaking these rules WILL cause conflicts and data loss.

### Rule 1: Zone Enforcement (CRITICAL)

Before editing ANY file, check if it belongs to YOUR zone (see Zone Map below).

- ✅ File is in YOUR zone → proceed
- ⛔ File is in ANOTHER agent's zone → **STOP and warn the user:**
  "⚠️ This file belongs to [Agent Name]'s zone. I should not edit it. Please give this task to [Agent Name], or explicitly confirm you want me to proceed."
- ⚠️ File is in SHARED zone → check Locked Files below, then ask user for permission

### Rule 2: Lock Before Edit

Before editing a file, add it to the "Locked Files" section below.
After finishing, remove the lock and log the change in "Recent Changes".

### Rule 3: Never Edit Simultaneously

If a file is listed in "Locked Files" — do NOT touch it. Tell the user:
"🔒 This file is currently locked by [Agent Name]. Please wait or ask them to finish."

### Rule 4: Shared Files Need Permission

Files in the SHARED zone (root configs, package.json, etc.) require explicit user permission.
Always ask: "This is a shared file. May I edit it?"

### Rule 5: Always Identify Yourself

When updating this file, always sign your entries with your name and timestamp.

## 📌 Pre‑commit workflow

- **When an agent wants to edit a file**, it must:
  1. Check `.agents.md` → ensure the file is in its zone or request permission for SHARED files.
  2. Add the file to the **LOCKED FILES** list with its name, agent, and timestamp.
  3. Perform the edit.
  4. Commit using `git add` / `git commit` – the `pre‑commit` hook will run **lint‑staged** → `prettier` formats the changes automatically.
  5. After the commit succeeds, remove the entry from **LOCKED FILES** and add a line to **RECENT CHANGES**.

> **Note:** If the hook reports a formatting error, the commit is aborted. The agent should fix the formatting and retry.
