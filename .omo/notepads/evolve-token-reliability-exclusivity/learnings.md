### OZ 5.6 TimelockController facts (verified from installed source)

- Constructor `(uint256 minDelay, address[] proposers, address[] executors, address admin)`. Passing `admin = address(0)` makes the timelock **self-administered** (`DEFAULT_ADMIN_ROLE` held only by the timelock itself) — every role rotation must itself pass a 48h proposal. This is the recommended production posture; we hardcode `ZeroAddress`.
- Proposers automatically receive `CANCELLER_ROLE` as well.
- Custom errors to assert in tests: `TimelockInsufficientDelay(delay, minDelay)` (schedule below minimum), `TimelockUnexpectedOperationState` (execute before eta / after cancel), `AccessControlUnauthorizedAccount` (non-proposer/non-executor).
- 48h = 172800 seconds; `getMinDelay()` returns it.

### Ignition 0.15 gotchas hit (and fixed) during E2E validation

1. **Duplicate `m.call` ids**: two `m.call(evolveToken, "grantRole", ...)` on the same contract produce identical autogenerated future ids → IGN702. Fix: explicit `{ id: "grantAdminRoleToTimelock" }` / `{ id: "grantMinterRoleToTimelock" }`.
2. **Hardhat compiles only `src/**` + transitive imports** — OZ contracts never imported from `src/` get no artifact, so `m.contract("TimelockController")` and `getContractFactory("TimelockController")` both fail. Fix: import-only anchor `src/TimelockController.sol` (no contract declaration → no duplicate artifact name; the OZ artifact resolves by contract name).
3. **Submodules cannot receive parent futures**: `useModule(submodule)` takes no options in 0.15; parameters are static JSON only. The old `PaymasterModule` worked around this by deploying its own EVOLVE — with **zero constructor args** (IGN703), which had been silently breaking `deploy:local` since the AA task. Fix: deploy `EvolvePaymaster` inline in `index.js` where the `evolveToken` future is in scope; deleted `ignition/modules/Paymaster.js`.
4. **Pre-existing ENTRY_POINT checksum typo**: `0x5FF...57C578...` is checksum-INVALID (real EntryPoint v0.6 is `0x5FF137D4B0FdCD49dca30C7Cf57e578a02B420c4`, note `57e578`). The old module's constant crashed ignition's ABI encoding; `Paymaster.test.js` used a _different_ checksum-valid-but-wrong variant. Both fixed to the canonical address.
5. **One params file ≠ all networks**: `ignition-parameters.json` owner `0xfa3A...` is the Sepolia deployer; on the in-process hardhat network ignition deploys from hardhat#0 (`0xf39F...`), so ALL `m.call` wiring (pre-existing `setDNAVerification` included) reverted `UnauthorizedAccount`. Fix: new `ignition-parameters.local.json` (owner/proposer/executor = hardhat#0) used by `deploy:local`/`deploy:localhost`; the Sepolia file stays untouched. Deployer ≠ owner is indistinguishable from "wiring is broken" — always check which account ignition sends from.

## Task 3 — RewardMinter (2026-09-28)

### Pattern that worked

- **Submodule needing the timelock future**: `RewardMinterModule` internally `m.useModule(EvolveModule)` + `m.useModule(TimelockControllerModule)` — same dedup `EvolveFundModule` already relies on. Futures resolve to the single EVOLVE/timelock instances `DeployAllModule` deploys; module params stay static JSON (`initialMinter`, `rewardDailyLimit`/`faucetDailyLimit` string defaults "10000"/"1000"). Ignition 0.15 `m.contract` accepts contract futures + param futures mixed freely — only `useModule` options are restricted.
- **Rate limits testable without 10k txs**: limits are `immutable` constructor params; production values live as `DEFAULT_REWARD_DAILY_LIMIT`/`DEFAULT_FAUCET_DAILY_LIMIT` constants (documentation) that ignition passes explicitly. Tests deploy with 3/2.
- **Deterministic daily windows in tests**: `snapIntoWindow(60)` = evm_increaseTime to 60s past the next `block.timestamp / 1 days` boundary → ~86340s headroom, no test can straddle a rollover by accident; rollover test just +86400s. All via `evm_increaseTime`+`evm_mine`, zero real sleeps.
- **Lazy window counters**: single slot per counter (`window`, `count`); mismatched window ⇒ count reads as 0. Cheaper than unbounded `mapping(window => count)` and view functions (`rewardMintedToday`/`faucetMintedToday`) compute the reset for free.
- **ABI anti-slop probe**: asserting "no arbitrary-amount mint" via `interface.fragments` filter on `name.startsWith("mint")` accidentally catches the `minter` public getter — filter must exclude getter names (`f.name !== "minter"`) and sort before `deep.equal`.
- **Whitelist = single address slot + `setMinter`**, NOT an AccessControl role: rotation is one tx through the timelock (grant+revoke via a role would need two proposals or an extra admin function); old key irreversibly loses access the moment the slot is overwritten. Guarded by `DEFAULT_ADMIN_ROLE` (timelock).

## Task 6 — EVOLVE inherits LayerZero OFT (2026-09-29) — CRITICAL for Tasks 7/8/9

### Contract-level facts (verified empirically, commits 488b11e + 996eeff + b50c5c2)

- **Ownable base-ctor gotcha**: `OFT → OFTCore → OApp → OAppCore` does NOT forward constructor args to `Ownable` → solc error "No arguments passed to the base constructor". Most-derived contract must add `Ownable(initialOwner)` to its ctor modifier list (+ direct `import { Ownable }` — transitive imports are NOT visible). Also `OAppCore` ctor reverts `InvalidDelegate` on zero delegate → pass `initialOwner` as the OFT delegate, NOT address(0).
- **ZeroAddress lzEndpoint reverts at DEPLOY**: OAppCore ctor calls `endpoint.setDelegate(delegate)` — empirically reverts with endpoint=0 on hardhat/EDR. ALL test fixtures must deploy a real mock endpoint.
- **EVOLVE final ctor**: `(address initialOwner, uint256 maxSupply, address lzEndpoint)`; delegate = initialOwner; Ownable owner = initialOwner (so `setPeer` onlyOwner works for the deployer in tests).

### Test infrastructure (reusable for Tasks 8/9)

- **`test/helpers/lz-endpoint.js`** — shared `deployLzEndpointMock(owner)` helper: loads the PRECOMPILED `EndpointV2Mock` artifact from `@layerzerolabs/test-devtools-evm-hardhat` (v0.5.3) via `createRequire` + resolving `package.json` (its `exports` map only exposes `.` and `./package.json` — deep imports are blocked, file-read bypass is required). Artifact has no linkReferences/immutables → directly deployable.
- **`hardhat.config.js`: `hardhat: { allowUnlimitedContractSize: true }`** — the mock bytecode is ~26KB > EIP-170 24KB. DO NOT remove.
- **Two-chain bridge wiring** (see EVOLVEOFT.test.js): mockA(eid=1) + mockB(eid=2); `mockX.setDestLzEndpoint(remoteToken, remoteMock)` both ways; `tokenX.setPeer(remoteEid, zeroPadValue(remoteToken,32))` both ways; owner is LZ delegate+Ownable owner.
- **Type-1 executor options REQUIRED**: `0x0001` + 32-byte big-endian gas (34 bytes total, e.g. 200k). Empty options revert in the mock's ULN decoder (`LZ_ULN_InvalidWorkerOptions`). No `@layerzerolabs/lz-v2-utilities` installed — handcraft the bytes.
- **`_lzSend` requires msg.value EXACTLY == quoteSend(...).nativeFee** (`NotEnoughNative` otherwise). Mock's `receivePayload` try-catches lzReceive failures SILENTLY — if balances don't move, the wiring (peers/delegate) is wrong, not the token.
- **Bridge amounts must be divisible by 10^12** (sharedDecimals=6 dust removal): use `N * 10n**12n`.
- **Fee math sanity**: mock nativeFee ≈ 3e15 wei (~0.003 ETH) at gas=200k — signers have plenty.
